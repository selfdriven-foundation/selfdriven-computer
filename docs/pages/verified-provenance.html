The premise

Provenance stops where the stack turns opaque.

Today's Verified Context Graph runs in software, on CPUs, models and supply chains that nobody in the chain can inspect.

Three pressures make that assumption untenable.

Software-only provenance proves who signed what, and when. It cannot prove what the machine executed.

    The framework

    How a claim earns its level.

    Seal levels, the chip, the clock, the proof path, the cryptography, the supply chain and the rules that hold it together.

    Seal levels

    Five grades of evidence.

    Proposed grades for what backs a seal. Every level above 0 is a KERI digest, root, event or location seal; the difference is who and what stands behind it.

    • L0

      Unsealed

      Nothing; trusted by assumption. A closed third-party CPU or a hosted model API.

    • L1

      Self-attested

      Digest anchored in the operator's own key event log. An operator seals a dataset it publishes.

    • L2

      Witnessed

      Seal receipted by independent KERI witnesses. A build sealed and receipted by a witness pool.

    • L3

      Reproducible

      An independent party re-runs the work and gets the same hash. A reproducible build; a re-executed trace.

    • L4

      Silicon-rooted

      Produced on VCG-verified silicon, with a provenance clock and a publicly anchored proof. A run on selfdriven silicon.

    selfdriven silicon

    A chip that arrives with its own provenance.

    selfdriven silicon is a RISC-V processor laid out with an open process design kit, with every design file and fabrication step sealed. It is the root the five layers stand on.

    Who is building open silicon
    • 01

      Open silicon

      RISC-V gives an open instruction set. SkyWater SKY130, GF180MCU and IHP SG13G2 give open process data, so a design can be audited from instructions to layout.

    • 02

      selfdriven silicon

      A new generation of CPU on RISC, with universal I/O. Each design file, toolchain run and tape-out artefact is sealed as it is produced.

    • 03

      VCG silicon

      The fabricated chip, checked against its sealed design and enrolled as a node in the graph. It runs the provenance clock.

    • 04

      Edge hardware

      The same silicon in cameras and networked IoT devices, so data is sealed at the moment of capture.

    • 05

      Foundation ASIC

      A fixed-function chip for information compute: hashing, sealing and verification at volume.

    Instructional provenance clock

    The chip's own run becomes the evidence.

    Every executed instruction joins a hash chain. Each step's hash folds in the previous hash, the instruction, and the register and memory change it caused.

    hn = H( hn−1 ‖ instrn ‖ Δstaten )

    • 01

      A logical clock

      Steps are ordered by the chain, not by wall time. Wall time arrives when the chain head is anchored.

    • 02

      Checkpoints into identity

      At set intervals the chain head is sealed into the chip's key event log as an interaction event.

    • 03

      Leaks nothing

      Only digests leave the chip. Program, inputs and data stay with their owner until a dispute needs them.

    • 04

      Change one step, change every hash

      Each hash folds in the one before it, so a single altered step changes every hash after it. Try it below.

    Proof path

    A run counts only when an independent re-run matches.

    The pattern already runs on Bitcoin mainnet: BitVMX uses a virtual RISC-V CPU to produce execution traces, and a disputed trace is settled through on-chain challenges.

    • 01

      Program

      Compiled to RISC-V.

    • 02

      Run

      On VCG silicon.

    • 03

      Provenance clock

      Hashes every step.

    • 04

      Seal

      Chain head into the chip's key event log.

    • 05

      Anchor

      Chain head on a public ledger.

    • 06

      Verifier

      Re-runs the program and compares. Do the hash chains match?

    • Match

      Accepted

      The claim enters the graph with its seal level. Nothing is spent on-chain.

    • Mismatch

      Dispute

      Search over the trace finds the exact step where the runs diverged, and the dispute settles on-chain.

    Cryptographic posture

    Signatures are the pressure point.

    AES defines 128, 192 and 256-bit keys, and NIST says all three remain usable against quantum attack. Public-key cryptography is what breaks, and every seal here is signed.

    KERI already helps. Pre-rotation commits to the next keys only as digests, so they stay hidden until used, and a controller can rotate to post-quantum keys without changing its identifier.

    Silicon is the slow part. Fabrication lead times are long, so selfdriven silicon ships ML-DSA and SLH-DSA support from its first tape-out.

    • Signatures on key events and seals

      Ed25519 → ML-DSA

      ML-DSA (FIPS 204), with SLH-DSA (FIPS 205) for long-lived roots; dual-sign during transition.

    • Key establishment between nodes

      X25519 / ECDH → ML-KEM

      ML-KEM (FIPS 203), paired with a classical exchange until 2035.

    • Hashing for seals, traces and the clock

      SHA-2 / Blake3: keep

      Each digest carries its algorithm code so it can change.

    • Encryption of sealed artefacts

      AES-256: keep

      No change needed.

    Supply chain

    Third parties stay, graded and bounded.

    Replacing every third-party CPU and model at once is neither possible nor needed. Each one gets a place in the graph and a seal level.

    • 01

      Inventory

      Every third-party component is a node in the graph. A closed CPU or a hosted model usually sits at L0.

    • 02

      Bound

      Results inherit the lowest level beneath them. Signing seals, running the clock and verifying proofs happen only on selfdriven silicon.

    • 03

      Cross-check

      Sensitive work runs on two independent stacks. Matching trace hashes raise confidence; a mismatch is evidence in itself.

    • 04

      Models as sources

      Weights, training-data lineage and inference runs are sealed. Outputs enter the graph as claims carrying the model's identity and level.

    • 05

      Replace from the bottom

      Components are swapped for verified ones starting with silicon, because every layer above inherits from it.

    Design rules

    Seven rules hold at every layer.

    The rules this framework holds to. The site's seven principles for a clocked, verifiable operating model sit alongside them.

    Read the principles
    • 01

      Verify, don't trust

      Any claim a layer makes can be checked by a third party without the operator's cooperation.

    • 02

      Provenance starts at the bottom

      A seal is only as strong as the layer beneath it, so the chain begins at silicon.

    • 03

      Seal each layer on its own

      A failure in one layer stays visible and bounded.

    • 04

      Open where it matters

      Instruction set, process design kit and chip design are open to audit. Closed parts carry a lower seal level.

    • 05

      Execution is evidence

      What ran, and in what order, is hashed as it runs.

    • 06

      Anchor in public

      Proofs settle on a public ledger, so no single party can rewrite the record.

    • 07

      Stay crypto-agile

      KERI pre-rotation moves keys and algorithms without re-issuing identity.

    Pathway

    From soft VCG to silicon in five stages.

    Each stage raises the highest seal level the stack can reach, and closes on a gate before the next one starts.

    1. Today

      Soft VCG, v1 to vn

      up to L2

      GateEvery layer emits seals and records its level.

    2. Stage 2

      Reproducible execution

      up to L3

      Builds are reproducible; programs compile to RISC-V and run on a virtual CPU that emits trace hashes.

      GateAn independent re-run matches the trace hash.

    3. Stage 3

      Anchored proofs

      up to L3

      Prototype silicon

      GateThe chip's trace matches the virtual CPU's trace for the same program.

      L4 end to end

      Verified chips ship in compute nodes and edge devices, with the foundation ASIC sealing at volume.
